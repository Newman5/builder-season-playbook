# Builder Agent Prompt — Builder Season Playbook Landing Page

Create a product landing page for:

# Builder Season Playbook

Core positioning:

“Builder Season Playbook helps communities run long-form hackathons that produce real progress instead of demo theater.”

This is NOT a typical hackathon product.

The tone and positioning should emphasize:

* consistency over hype
* real progress over demos
* operational simplicity
* public accountability
* lightweight systems
* open-source builder culture
* calm, focused execution

The page should feel:

* operational
* trustworthy
* calm
* documentation-inspired
* indie/open-source
* practical
* systems-oriented

Avoid:

* flashy startup aesthetics
* growth-hacker language
* aggressive marketing tone
* “10x” messaging
* AI-generated-looking design
* overly corporate SaaS vibes

Visual inspiration:

* editorial layouts
* GitHub / Linear / Basecamp docs aesthetics
* clean typography
* screenshots and diagrams
* subtle motion only
* structured sections
* workflow-oriented visuals

Context:
This product emerged from running a real builder season / hackathon called “Piece of Pie” with:

* weekly accountability
* public progress updates
* GitHub tracking
* builder dashboards
* newsletters
* operational workflows
* admin systems
* lightweight project management
* real users and feedback loops

Primary audience:

* hackathon organizers
* developer communities
* open-source ecosystems
* DAOs
* incubators
* ecosystem growth teams
* community coordinators
* educational organizations
* organizations similar to Gimbalabs and Cardano ecosystem teams

Product priorities:

1. Digital downloadable toolkit/product
2. Consulting funnel for setup/admin support
3. Longer-term ecosystem operating system

Primary CTA:

1. “Run Your Own Builder Season”
2. “Download the Playbook”
3. “Book a Strategy Call”

The landing page should structurally include:

1. Hero Section

* Strong positioning headline
* Subheadline explaining the framework
* Primary CTA
* Secondary CTA
* Possibly include a dashboard or workflow screenshot

2. Problem Section
   Describe problems with traditional hackathons:

* demo theater
* low follow-through
* organizer burnout
* shallow engagement
* hype without sustained progress
* difficulty tracking builder activity
* weak accountability

3. Builder Season Framework
   Explain:

* long-form cadence
* weekly updates
* public accountability
* visible progress
* lightweight operations
* real-user feedback
* sustainable momentum

4. What’s Included
   Potential downloadable components:

* templates
* workflows
* onboarding docs
* newsletter templates
* X/Twitter templates
* GitHub project structures
* YAML/CSV examples
* admin checklists
* operational playbooks
* dashboard systems
* automation examples
* Obsidian vault
* examples from real builder seasons

5. Screenshots / Examples
   Design placeholder areas for:

* dashboards
* GitHub projects
* builder feeds
* workflows
* kanban boards
* update examples
* operational systems

6. Who It’s For

* ecosystem teams
* DAOs
* accelerators
* open-source communities
* dev education programs
* community-led hackathons

7. Philosophy Section
   Possible themes:

* “Build in public”
* “Visible progress matters”
* “Consistency beats intensity”
* “No judges. No fluff.”
* “Users and programmers party together.”
* “Real users count more than demo day.”

8. Open Source + Consulting
   Position the product as:

* open-source friendly
* customizable
* operationally lightweight
* optionally supported through consulting/admin setup help

9. Final CTA
   Strong operational tone.
   Not hypey.
   Confident and practical.

Technical / implementation notes:

* Make this easy to evolve into a real product site
* Prefer modular sections/components
* Use placeholder copy where needed
* Optimize for future screenshots and examples
* Build for future additions:

  * testimonials
  * case studies
  * proposal deck integration
  * pricing
  * consulting funnel
  * downloadable assets

Important:
This is not merely a “hackathon toolkit.”
It is a repeatable framework for running builder ecosystems with visible progress and sustained momentum.
